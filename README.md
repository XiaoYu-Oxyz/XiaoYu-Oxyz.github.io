# 实验课提醒（多班级 · 离线 · GitHub Pages）

一个面向班级实验课表的纯静态 Web 应用：多班级切换、Excel 导入/导出、按周显示、本周筛选、手机端自适应，构建后可直接部署到 GitHub Pages。

- 部署入口：[index.html](index.html)
- 当前仓库：`XiaoYu-Oxyz/XiaoYu-Oxyz.github.io`
- 用户主页：<https://xiaoyu-oxyz.github.io/>
- 当前构建：3 个班级、56 条实验
- 数据公开提示：部署到 GitHub Pages 后，`data/*.xlsx`、`index.html` 和本 README 都会公开，请勿放敏感信息。

---

## 1. 项目定位

本项目不是带后端的排课系统，而是一个**构建时固化数据、运行时完全离线**的静态页面。

- 运行时只有一个 `index.html`，不请求服务器，不读取 `data/`，不依赖第三方 CDN。
- 班级数据来自 `data/*.xlsx`，在构建阶段校验后写入 `index.html` 的惰性 `<template>`。
- 浏览器里的增删改只保存在当前站点的 `localStorage`，要发布必须导出 xlsx、覆盖 `data/`、重新 build、提交 `index.html`。
- GitHub Pages 只负责静态托管，不提供登录、权限、数据库或服务端写文件能力。

## 2. 功能

### 2.1 多班级

- 班级下拉框位于标题右侧。
- 班级名来自 xlsx 文件名：`data/Z1.xlsx` → 班级 `Z1`。
- 默认选中第一个班级，之后记住上一次选择。
- 班级顺序按自然排序；支持的班级数量受浏览器和页面性能限制，实际使用远低于上限。
- 页面导入时新建的班级只在本机存在；导出该班 xlsx、放入 `data/` 并 build 后才成为部署默认班级。

### 2.2 实验数据

- 每行包含日期、周次、星期、节次、实验名称、实验地点。
- 页面按日期升序显示；今天、明天、已结束分别有颜色和标签提示。
- 第 1 周星期一由 `data/设置.json` 的 `week1` 决定，所有班级共用。
- 表格默认显示当前班级的全部实验；本周筛选开启时只隐藏更早的已结束实验。

### 2.3 本周筛选（默认勾选）

标题右侧、班级之后有一个复选框：

```text
☑ 已结束仅显示本周
```

行为：

- **默认勾选，每次刷新都会恢复勾选**，不持久化取消状态。
- 保留**本周一及以后**的实验；更早的已结束实验隐藏。
- 今天、明天和未来实验始终显示。
- 复选框旁显示 `显示 X / 共 Y`。
- 取消勾选后显示该班全部实验。
- 筛选只影响显示；导出 Excel 仍导出该班全部数据，不会因为筛选丢数据。
- 如果筛选后没有任何记录，会提示“本周一及以后没有实验；已隐藏 N 条更早记录”，并提示取消勾选查看全部。

> “本周”按浏览器本地日期的自然周计算，星期一为一周起点。

### 2.4 手机端布局

- 宽度 **≤ 940px** 时，表格自动变为紧凑两行列表，不再左右滑动。
- 第一行：日期、星期、周次、节次、今天/明天/已结束标签。
- 第二行：实验名称、实验地点。
- 桌面端（≥ 941px）保持原表格布局。
- 已验证 390px、820px、900px 无横向滚动；941px 起恢复桌面表格。

### 2.5 Excel 导入/导出

- 导入 `.xlsx`；导出当前班级 `${班级}.xlsx`。
- 导出 sheet 名固定为 `实验安排`，包含 6 列：日期、周次、星期、节次、实验名称、实验地点。
- 空班级也可导出只有表头的空表。
- 导入默认合并；同一文件也可选择替换当前班。
- 文件名与当前班不一致时，默认按文件名切换/新建；也可选择忽略文件名，导入当前班。
- 页面导入新建的班级只在当前浏览器存在，必须导出并 build 后才发布。
- 导出始终包含该班全部实验，不受本周筛选影响。

### 2.6 “删除实验”按钮（重要）

当前版本的顶部“删除实验”**不是批量删除功能**，而是一个锁定入口：

1. 点击后禁用全部交互控件；
2. 给 `body` 加 `locked`，阻断后续点击、键盘、提交、输入等事件；
3. 使用 `location.replace('./404.html')` 跳转到同目录的 [404.html](404.html)。

这意味着：

- 该按钮**不会删除任何实验数据**。
- 跳转后浏览器返回历史里不会保留本页面（使用 `replace`）。
- `404.html` 页面自身的“返回上一页 / 回到首页”按钮仍然可用；如果连这些也要禁用，需要单独修改 404 页面。
- 旧批量删除代码仍保留在源文件中，但没有入口，属于未启用代码。
- 这是**有意设计**，不是页面错误。

### 2.7 本机存储与恢复

- 每班数据独立保存在 `localStorage`，键名带项目前缀和班级名。
- 空数组是有效状态：某班删空后刷新仍为空。
- “恢复默认数据”只恢复当前班级，不影响其他班级。
- 本地新建、尚未进入 `data/` 的班级，恢复按钮不可用。
- 旧版单班数据在选中 Z2 时自动迁移到 Z2；旧键在成功迁移后清理。
- 页面内修改只在本机生效；发布必须走“导出 → 覆盖 data → build → 上传”。

## 4. 数据格式

### 4.1 文件与工作表

- 每班一个 `.xlsx` 文件；文件名去掉 `.xlsx` 就是班级名。
- 只读**第一个工作表**；sheet 名随意，不参与班级命名。
- 表头必须在第一个非空行内，列顺序不限。
- 必需列：

```text
节次、实验名称、实验地点
```

- 时间列至少满足一组：

```text
日期
或
周次 + 星期
```

- 两组时间列可以只出现一组，也可以同时出现。
- 如果只出现 `周次` 或 `星期` 其中一个，且同时有 `日期`，则使用日期；如果连日期也没有，导入失败。
- `日期` 列和 `周次/星期` 列可以同时存在；每行独立判断。

### 4.2 每行时间规则

优先级从高到低：

1. `周次` + `星期` **都有效**：使用周次+星期推算日期；
2. 否则，`日期` **有效**：使用日期；
3. 两者都没有有效时间：整次失败。

更具体地：

- 两组都填且周次+星期有效 → **周次+星期优先**。
- 两组都填但周次+星期无效/不完整 → **回退日期**。
- 日期无效或为空，但周次+星期有效 → 使用周次+星期。
- 周次/星期只填了一个，且日期有效 → 忽略不完整的一组，使用日期。
- 周次/星期只填了一个，日期也无效/为空 → 失败。
- 两组都无效/为空 → 失败。

失败行为：

- **页面导入**：整次导入失败，不写入任何数据，已有数据不变。
- **build**：整个构建失败，不覆盖 `index.html`。

### 4.3 周次与日期换算

```text
日期 = week1 + (周次 - 1) × 7 + (星期 - 1)
```

- `week1` 是第 1 周星期一，来自 `data/设置.json`。
- 周次范围：1–1000。
- 星期支持 1–7、星期一至星期日、周一至周日、礼拜一至礼拜日等常见写法；数字 0 按星期日处理。
- 日期推荐 `YYYY-MM-DD`；Excel 日期单元格也可识别。

### 4.4 示例

只有日期列：

```text
日期         | 节次    | 实验名称 | 实验地点
2026-09-18   | 第3-4节 | 机械设计 | A114
```

只有周次+星期列：

```text
周次   | 星期   | 节次    | 实验名称 | 实验地点
第2周  | 星期五 | 第1-2节 | 机械设计 | A114
```

日期和周次+星期都有：

```text
日期         | 周次   | 星期   | 节次    | 实验名称 | 实验地点
2026-09-18   | 第3周  | 星期五 | 第3-4节 | 机械设计 | A114
```

空班级可以只有表头，没有数据行。

### 4.5 全局设置

`data/设置.json`：

```json
{
  "version": 1,
  "week1": "2026-08-31"
}
```

- `week1` 必须是非空、有效的 `YYYY-MM-DD` 日期；按约定它应是第 1 周星期一。构建脚本校验日期格式，不强制校验星期几，请自行保证语义正确。
- 页面上的“第 1 周星期一”修改只对本机生效；发布默认值需要修改该 JSON 后 build。
- “恢复默认数据”不会清空 `week1`。

### 4.6 内置数据结构

构建后的模板版本为 `version: 2`：

```json
{
  "version": 2,
  "week1": "2026-08-31",
  "classes": [
    {
      "id": "Z1",
      "experiments": [
        {
          "date": "2026-10-12",
          "period": "第5-6节",
          "name": "电工电子实验",
          "place": "218"
        }
      ]
    }
  ]
}
```

运行时使用 `date` 作为唯一时间依据，周次和星期由 `week1` 动态计算。

## 5. 开发与构建

### 5.1 环境

- Python 3.9+
- `openpyxl>=3.1,<4`
- 构建机需要 Python；网页运行不需要 Python。

安装：

```bash
python -m pip install -r requirements.txt
```

如果当前 `python` 没有 `openpyxl`，先安装；也可以使用你自己环境中已装好依赖的 Python。根目录 `.bat` 是作者本机快捷脚本，含绝对路径，不建议在其他机器直接运行。

### 5.2 只改数据

1. 页面里添加/删除/导入；
2. 选择当前班，点“导出 Excel”；
3. 用下载的 `${班级}.xlsx` 覆盖 `data/${班级}.xlsx`；
4. 如有第 1 周变化，同步修改 `data/设置.json`；
5. 构建并校验：

```bash
python build-html.py
python verify-csp.py
```

正常输出示例：

```text
built index.html: 3 classes, 56 experiments total
  Z1: 22 条
  Z2: 24 条
  Z5: 10 条
```

### 5.3 改代码

如果修改了 `<style>` 或 `<script>`：

```bash
python verify-csp.py --apply
python build-html.py
python verify-csp.py
```

顺序不能反：

1. `--apply` 按最终 UTF-8/LF 字节重算 CSP 哈希并同步 `index.html`；
2. `build-html.py` 写入最新数据；
3. 最后 verify。

只改数据不需要 `--apply`；改代码必须重算哈希，否则浏览器会拒绝执行。

### 5.4 构建产物

- `build-html.py` 读取 `data/*.xlsx` 和 `data/设置.json`；
- 校验表头、日期/周次、字段长度、控制字符、重复班级；
- 转义 `<>&` 后写入 `<template id="defaultData">`；
- 同时写 `实验提醒.html` 和 `index.html`；
- 自动调用 `verify-csp.py`。

构建失败时不会覆盖现有 HTML，先修数据再重试。

## 7. 安全设计

### 7.1 已实施

- CSP 使用 SHA-256 哈希放行内联 `<style>` / `<script>`，不含 `'unsafe-inline'` / `'unsafe-eval'`；
- `require-trusted-types-for 'script'`，仅保留受控 `xlsx-xml` 策略；
- 无外部脚本、样式、字体、图片或网络请求，`connect-src 'none'`；
- 动态内容全部用 `createElement` / `textContent` 构建，不使用 `innerHTML`；
- xlsx 导入限制文件大小、ZIP 条目、解压总量、压缩比、XML 大小、行列数和字段长度；
- 导入只读缓存值，不执行公式；导出使用 `inlineStr` 文本；
- 构建时校验并转义 `<`、`>`、`&`，防止模板注入；
- `localStorage` 按班级隔离，校验 schema、类型、长度和条数；
- `verify-csp.py` 检查哈希、模板、默认数据解析和源/部署字节一致。

详见 [SECURITY.md](SECURITY.md)。

### 7.2 残余风险

- GitHub Pages **不能设置** `frame-ancestors`、`X-Frame-Options`、HSTS 等响应头；点击劫持没有可靠防护。为避免预览/iframe 环境误跳 404，项目已移除 JS frame-buster。
- GitHub Pages 站点和仓库文件默认公开；没有登录、权限或访问控制。需要私密数据时不要使用公开 Pages。
- `*.github.io` 同账号项目共享源，`localStorage` 可能被同源其他项目读取/覆盖；项目前缀只能防误撞。
- 页面是纯客户端应用；有 DevTools 的用户可以修改自己的数据。
- `404.html` 是独立页面，不受主应用的 CSP 约束；它自身的内联样式/脚本在部署后仍会执行。它不含用户数据。
- 免费 GitHub Pages 没有 WAF/DDoS 防护。

如果数据敏感或需要访问控制，应改用支持身份认证和自定义响应头的托管方案，而不是仅调整前端代码。

## 9. 常见问题

### Q1：为什么 Z1 有 22 条，但页面只看到 14 条？

默认勾选了“已结束仅显示本周”。Z1 中 10 月 26 日之前结束的 8 条被隐藏，只显示 10 月 28 日及以后。取消勾选即可看到全部 22 条。

如果显示 `0 / 0` 或“暂无实验安排”，说明浏览器里 Z1 的 `localStorage` 是空的/旧的；选中 Z1 后点“恢复默认数据”。如果本地有未导出的改动，先导出 xlsx 再恢复。

### Q2：改了 `data/*.xlsx`，网页没变化？

页面运行时不读取 `data/`；需要重新 build，并提交新的 `index.html`：

```bash
python build-html.py
python verify-csp.py
git add -A
git commit -m "data: 更新"
git push
```

### Q3：build 报“找不到表头”？

检查：

- 是否只读第一个工作表；
- 是否包含 `节次`、`实验名称`、`实验地点`；
- 是否至少有 `日期` 或 `周次+星期`；
- 表头是否在第一个非空行、拼写是否正确。

### Q4：某一行明明有周次，为什么 build 失败？

如果该行没有有效日期，且周次/星期不完整或无法识别，就会失败。需要同时提供有效的 `周次` 和 `星期`，或提供有效 `日期`。

### Q5：点“删除实验”为什么跳到 404？

这是当前版本的有意行为，不执行删除。页面会先锁定，再跳转同目录 `404.html`。如果需要真正的删除功能，需要重新设计该入口和权限/确认流程。

### Q6：手机为什么没有横向滚动条？

≤ 940px 已切换为两行列表，所以不需要横向滚动。桌面宽度 ≥ 941px 才显示原表格。

### Q7：GitHub Pages 打开是 404？

检查：

- `index.html` 是否在仓库根目录；
- Pages 是否设置为 `main` + `/ (root)`；
- 是否等待了 1–3 分钟；
- 是否访问了错误的项目路径；
- 是否被浏览器缓存（无痕窗口/`Ctrl+F5`）。

### Q8：Git push 连接被重置？

常见原因是 Git 没有走系统代理。需要给 Git 单独配置 HTTP/HTTPS 代理，或换网络/VPN。不要用 `http.sslVerify=false` 绕过证书校验。

## 10. 已知限制

- 纯静态页面，没有后端、数据库、登录或服务端写文件能力。
- 页面内修改只在本机 `localStorage`；发布必须手动 build + 上传。
- GitHub Pages 本身不提供访问控制；公开仓库/Pages 的数据就是公开的。
- 本周筛选按浏览器本地时间和自然周计算；不同设备可能因时区/日期不同而显示不同。
- 筛选状态不持久化，刷新后总是回到勾选状态。
- “删除实验”不是删除，而是锁定 + 404；404 页面自身按钮仍可用。
- 旧批量删除代码仍在源文件中，但当前无入口。
- `*.github.io` 同源 `localStorage` 不能做到路径级隔离。
- `.bat` 快捷脚本包含作者本机绝对路径，不适合直接分发。
- 本仓库未声明 License；如需开源分发，请补充 `LICENSE`。

## 11. 维护约定

1. 改代码后必须执行：

   ```bash
   python verify-csp.py --apply
   python build-html.py
   python verify-csp.py
   ```

2. 只改数据时不要执行 `--apply`，避免不必要的哈希变化。
3. 不要直接编辑 `index.html` 的 CSP 或 `<template>`；以 `实验提醒.html` 为源，build 会覆盖。
4. 保持 HTML/Python/Markdown/JSON 为 UTF-8、LF；`.gitattributes` 已配置。
5. 不要提交 `__pycache__/`、导出的临时 xlsx、token、`.env`。
6. 部署前确认 `404.html` 与 `index.html` 同目录。
7. 数据涉及个人信息时，先确认是否允许公开，再决定是否使用 GitHub Pages。
