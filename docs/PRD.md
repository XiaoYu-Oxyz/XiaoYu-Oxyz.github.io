## 0. 一页纸摘要

**给谁**：需要在手机上随时确认"下次实验在哪、几点、要不要带东西"的工科学生；以及改 Excel 维护数据的课代表/老师。

**解决什么**：学校教务系统里的实验安排又长又难找，微信群里发的表格会过期、会被刷走。本产品把一份 Excel 变成**一个可离线打开、能订阅到手机日历、能自己改、能打印**的课表页。

**怎么做到零成本**：
- 数据在构建期从 `data/*.xlsx` 注入 `index.html` 的 `<template>`，运行时**不发任何网络请求**；
- 用户改动存 `localStorage`，可以再导出成 xlsx/json 覆盖回仓库；
- 严格 CSP + Trusted Types，页面没有 `innerHTML`；
- 五层自动化测试（Python 42 · 逻辑 52 · UI 冒烟 12 段 · 课表 50 项 · 视觉 8 视口 ×2 引擎）守住回归。

## 1. 背景与问题

现状（改造前）：

| 问题 | 具体表现 |
|---|---|
| 数据在 Excel 里躺着 | 每次想看下次实验都要开电脑、找文件、算周次 |
| 表格一行挤一天 | 手机上看要横着拖动 |
| 群里发的截图会过期 | "这周的课"截图上没有日期高亮，分不清是第几周 |
| 手机日历里没有实验 | 学生要自己一条条手输提醒 |
| 改一条数据要重新发文件 | 课代表改一次就刷屏一次 |
| 老手机打不开新页面 | 2017 年的机型（如 vivo Y66i，360×640）一打开就白屏 |

## 2. 目标与非目标

### 2.1 目标（可衡量）

| 目标 | 衡量方式 | 当前值 |
|---|---|---|
| G1 打开就能看到"下一次实验" | 首屏出现提示条的比例 | 100%（有未来实验时） |
| G2 手机首屏能看到实验内容 | 首行距顶 ≤ 380px | 320:342 / 360:296 / 横屏:191 / 390:275 |
| G3 零网络依赖 | 运行时 `connect-src 'none'` | 已强制（CSP） |
| G4 单文件可离线 | `index.html` 单文件双击可开 | 是（`file://` 自测通过） |
| G5 数据可自助维护 | 不改代码即可更新数据 | `data/*.xlsx` + `build-html.py` |
| G6 打印可直接贴到教室门口 | A4 一页多行、不切行 | `break-inside: avoid` + 表头跨页重复 |
| G7 读屏可用 | NVDA/VoiceOver 清单通过 | 清单见 [ACCESSIBILITY.md](../ACCESSIBILITY.md)（人工复核仍需真机） |

### 2.2 非目标（明确不做）

- **不做后端**：没有账号、没有数据库、没有 API。跨设备同步靠"导出 → 覆盖仓库 → 重新部署"。
- **不做实时多人协作**：不同人的浏览器各自存本机数据。
- **不接管教务系统**：不爬取、不自动导入，数据由维护者提供。
- **不做原生 App**：不上架应用商店，不打包 APK/IPA。
- **不引入框架与构建工具**：没有 React/Vue/Webpack/Vite；`index.html` 就是产物。
- **不做多语言**：只面向中文用户。
- **不做账号与权限**：只有 `?mode=ro` 这一种"只读链接"的弱约束。

> 被否决过的具体功能见 §10，不要重复提出。

## 3. 用户与场景

### 3.1 用户画像

| 画像 | 描述 | 关键诉求 |
|---|---|---|
| P1 学生（主要） | 手机为主，Android 中低端机或 iPhone；每到实验周才打开 | 下次实验在哪、几点、带什么；能不能加进手机日历 |
| P2 课代表 | 会用 Excel；负责把老师给的安排录进 `data/` | 改一条不要动代码；改完别把页面搞坏 |
| P3 老师/助教 | 只在电脑上打印或转发 | 打印出来清楚、能贴在教室门口 |

### 3.2 核心场景

| 编号 | 场景 | 期望 |
|---|---|---|
| S1 | 周五晚上想知道下周一几点到哪 | 打开页面 → 顶部提示条直接给"下一节"含节次时间与地点 |
| S2 | 想知道这学期还有几次机械设计 | 搜索"机械设计" → 只剩相关行，显示"3 / 27" |
| S3 | 老师临时改地点 | 点「操作 → 编辑实验」→ 改地点 → 保存 → 本机立即生效 |
| S4 | 想让手机日历提前 30 分钟提醒 | 点「导出日历(.ics)」或用订阅地址导入 |
| S5 | 课代表把改好的安排发给全班 | 导出 xlsx → 覆盖 `data/Z2.xlsx` → 提交 → 页面自动更新 |
| S6 | 打印一份贴教室 | Ctrl+P → 表头带班级/日期/筛选说明，行不被页边界切断 |

### 3.3 关键任务流

**看课（P1）**：打开链接 → 自动定位到今天/下一节 → 顶部提示条 → 点提示条跳到对应行 → 需要时展开备注。

**改数据（P2）**：改 Excel → `python validate-data.py` 体检 → `python build-html.py` → `python verify-csp.py` → 提交 → CI 自动复跑。

## 4. 术语

| 术语 | 含义 |
|---|---|
| 班级 | 一套实验安排的单位，标识即文件名（如 `Z1`） |
| 节次 | 学校的时间片，如 `第3-4节`；可连写 `第3-8节`，也可顿号分隔 |
| 周次 | 从第 1 周星期一（`week1`）起算的序号，第 1 周为 1 |
| 下一次实验 | 今天及以后最近的一条；今天有则优先今天 |
| 当前筛选 | "已结束仅显示本周" + "只看冲突" + 搜索 三者叠加的结果 |
| 只读模式 | URL 带 `?mode=ro`，隐藏所有编辑入口，不写本机数据 |

## 5. 功能需求

优先级：**P0** 必须有（缺了产品不成立）／**P1** 应该有／**P2** 可以有。
每条需求带验收标准（Acceptance），可直接对照测试。

### 5.1 A · 数据与构建

| ID | 优先级 | 需求 | 验收标准 |
|---|---|---|---|
| A1 | P0 | 从 `data/*.xlsx` 读取班级数据 | 3 个班共 65 条全部进入页面；行数、日期、节次与 Excel 一致 |
| A2 | P0 | 支持"日期"或"周次+星期"两种时间写法 | 只填日期可导入；只填周次+星期可导入；两者都有时**周次+星期优先** |

## 6. 非功能需求（NFR）

### 6.1 性能预算

| 指标 | 预算 | 实测 |
|---|---|---|
| 页面体积 | ≤ 300KB（gzip 前） | `index.html` ≈ 265KB |
| 运行时网络请求 | 0 | 0（`connect-src 'none'`） |
| 首屏渲染（65 条） | ≤ 50ms | ≈ 0.7ms |
| DOM 节点 | ≤ 1000（列表视图） | ≈ 483 |
| 时钟刷新 | 30s 一次，不做重布局 | 只改文本节点 |

### 6.2 兼容矩阵

| 环境 | 现状 |
|---|---|
| Chrome / Edge 桌面 | 主目标，UI 冒烟 + 视觉冒烟覆盖 |
| Safari 桌面（WebKit） | 全部 JS 测试双跑 |
| Android Chrome（含 2017 老机型） | 360×640 视觉冒烟覆盖；`replaceChildren` polyfill |
| iOS Safari | 建议列表自绘兜底；datalist 原生不可用 |
| `file://` 直接双击 | 可用（无网络依赖），但 `.ics` 订阅链接需要 http(s) |
| 打印（A4 纵向） | `@page margin: 12mm`、表头重复、行不切 |

### 6.3 可维护性 / 可测试性

- **单一产物**：`index.html` 由 `build-html.py` 从模板 + 数据生成，构建后必须与提交一致（CI 强制）。
- **改动即验证**：pre-commit 钩子在 `index.html`/`404.html`/`*.ics` 变更时自动跑 `verify-csp.py`。
- **不得引入依赖**：无 npm 运行时依赖（Playwright 只用于测试）。

## 7. 数据模型与约束

### 7.1 单条实验

| 字段 | 类型 | 必填 | 上限 | 说明 |
|---|---|---|---|---|
| `date` | `YYYY-MM-DD` | 是* | — | *与"周次+星期"二选一 |

| 项 | 值 | 说明 |

## 10. 已否决需求（不要重复提）

| 需求 | 否决理由 |
|---|---|
| 动态页面标题（"今天 2 节课"） | 浏览器标签页本来就窄，收益低；且跨天要额外重绘 |
| 手机端周视图 | 360px 宽塞 7 列必然要横向滚动，比卡片更差 |
| 地点"待定"高亮 | "待定"是常态不是异常，高亮会满屏黄色 |
| 打印课表视图 | 课表在纸上比列表更占位置，且信息密度反而低 |
| 课表内行内编辑 | 格子太小，误触率高 |
| 「只看今天」按钮 | 与顶部提示条功能重复 |
| 撤销栈扩到 3 步 | 使用频次低，占内存与心智 |
| 批量编辑地点/备注 | 需求未证实，交互复杂 |
| 多学期支持 | 数据结构要加一维，收益不抵复杂度 |
| 备注里的链接可点 | 会引入外链与钓鱼风险，CSP 也不允许 |
| 浏览器通知 / PWA / Service Worker | 需要用户授权且经常被拒；离线已由单文件满足 |
| 后端同步 | 违背"零后端"定位 |
| 拆分文件 / 换框架 / 国际化 | 会破坏"单文件可双击打开" |
| CSS 变量 token 化 | 260KB 单文件里收益有限 |
| 删除标记列 | 冲突信息需要这一列承载 |
| 冲突用条纹表示 | 与"已结束"灰底叠加后不可辨 |
| `data.json` 懒加载 | 65 条数据没必要再发请求 |
| 字号全改 `rem` | 93 处 px 字号，重构风险大于收益；浏览器缩放已可用 |
| 日期超出学期范围警告 | 用户判断价值不足（可再议） |
| 周视图方向键翻周 / `?week=` 链接 / `prefers-contrast` | 用户明确"都不改" |
| 长节次在日历里拆段 | 用户只选了另外两项 |
| 导入前自动快照 / "未导出"提示 / 单条复制 | 用户明确不要 |
| 删除模式全选反选 / 导入 diff 明细 | 用户明确不要 |

## 11. 已知限制与风险

| 限制 | 影响 | 现状 |
|---|---|---|
| 无后端 | 换设备要重新导入 | 有导出/导入与订阅兜底 |
| `.ics` Content-Type 由 GitHub Pages 决定 | 个别客户端订阅可能失败 | 可用"导出 .ics 再导入"绕过 |
| 真实 NVDA/VoiceOver 未做真机复核 | 实际朗读效果可能有差异 | 人工清单已就绪 |
| 课表行标签不显示时间 | 44px 列宽放不下 | 用节次序号 + 提示条补足 |
| `updatedAt` 当前滞后于 data 提交 | 页面显示旧日期 | 可跑 `build-html.py --stamp` 更新 |
| 老机型 WebView 可能 < Chrome 60 | 部分新语法降级 | 已 polyfill 关键 API，未做完整回归 |
| 真机未验收 | 读屏/触控只能靠手工复核 | 清单在 ACCESSIBILITY.md |
