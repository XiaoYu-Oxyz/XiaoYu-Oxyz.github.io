# CrseCue 止损点（v2）

> **用途**：内部决策依据。约束"还要不要继续改"，不是功能说明、不是对外承诺。
> **怎么用**：任何一条改动（含 AI 建议）先过第 2 节四问；过不了就不做，过得了按第 10 节核成本。
> **一句话**：AI 只能提出"更好"、提不出"不改会坏"的时候，就停。

---

## 1. 产品定位与非目标

实验课提醒：一个班用一个静态页。

**只服务三件事**：① 打开就知道下一节实验在哪、几号几点；② 改完不会丢；③ 能导出/订阅到手机日历按时提醒。

**明确非目标**：不做营销落地页、不做转化漏斗、不做账号体系、不做多学期并存、不接后端。

> 因此任何"提升转化率 / 强化 CTA / 增强信任感 / 重做叙事"的建议，直接判为**不适用**，不进评审。

## 2. 判断公式（每条改动过四问）

| # | 问题 | 答"否"的动作 |
|---|---|---|
| 1 | 对应哪条目标（第 3 节）或哪条门槛（第 4 节）？说不出来 | 不改 |
| 2 | 不改会不会造成实际损失（迟到/丢数据/用不了）？不会 | 不改 |
| 3 | 改完能否验证（命令、断言、观察点）？不能且成本高 | 不改，或先做验证 |
| 4 | 是否引入更大风险（破红线、扩回归面、改架构）？会 | 不改 |

**分级标签**（动手前先贴，只做前两级）：

| 级别 | 判据 | 处理 |
|---|---|---|
| 阻断 | 迟到、数据丢失、订阅失效、手机无法操作、CI 红 | 立即修 |
| 高收益 | 有明确使用场景，改动 ≤1 文件 + 1 断言，可自测 | 修 |
| 锦上添花 | 措辞、颜色偏好、留白、图标风格、动效手感 | **不做**，进第 13 节 |

## 7. 反例库（这些"看起来对"的判断会被误判）

| 规则 | 会被误判的写法 | 正确判据 |
|---|---|---|
| 首屏能看到下一节 | "首屏看不到就是 bug" | 用户可能已滚到列表中部 → 判据是**完整可见**，不是首屏 |
| 完整可见 | "必须让整组都显示" | 整组高于一屏时无法做到 → 降级为**组首贴住安全区顶部** |
| 最小滚动 | "滚到居中更醒目" | 居中＝非最小；已经可见时必须 0 位移 |
| 差几像素 | "差 1px 也算没显示" | 用固定阈值 8px，且必须写成断言，不能每轮拍脑袋 |
| 对比度 4.5 | "描边不够 4.5 就是缺陷" | 描边是图形，门槛 **3:1**；文字才 4.5:1 |
| CI 绿 | "绿了就能发" | 还要求 build 后 `git status` 干净、CSP 哈希一致 |

## 8. 六个止损信号（可观察化：出现任意 2 条即停手）

| # | 信号 | 怎么观察（不用主观判断） |
|---|---|---|
| 1 | 目标已达成 | 第 3 节五项 Test 全绿 + 第 4 节门槛全达标 |
| 2 | 意见重复/矛盾 | 连续两轮出现同一句"可更清晰/更有冲击力"，或两轮建议互斥 |
| 3 | 边际收益递减 | 近两轮改动全部落在第 2 节"锦上添花"级 |
| 4 | 引入新风险 | 本轮需改 ≥2 文件或改架构/加依赖；或出现"改 A 坏 B" |
| 5 | 证据不足的大改 | 提议重做首屏/换叙事，但无真实使用反馈或数据 |
| 6 | 时间盒到线 | 第 1 轮 >2h / 第 2 轮 >1h / 第 3 轮仍在修非阻断项 |

## 9. 流程

1. **第 1 轮**：允许全量提意见，但必须按第 2 节分级；只处理"阻断 + 高收益"。
2. **第 2 轮**：只允许复核已改项与硬伤，不再开放全量审美建议。
3. **冻结条件**（满足即冻结，不看日期）：第 3、4 节全达标 + 硬伤清零 + 连续两轮无新增高优 + 时间盒用完。
4. **解冻条件**：**任何时候都可以重开，但提案必须有价值**——过第 2 节四问。触发源仅三类：真实使用碰到阻断/数据问题、部署环境变化（浏览器大版本、Pages 规则）、需求变化（新班级、新节次、新学期）。
   **"到期了""还能再改改"不是理由。**
5. 冻结后放弃项写进第 13 节，等反馈再开。

## 10. 成本闸门与时间盒

| 改动类型 | 改动面 | 预估 | 回归风险 | 准入要求 |
|---|---|---|---|---|
| 文档/文案 | 1 文件 | ≤20min | 低 | 过四问 |
| 色值/阈值 | 1 文件 + 1 断言 | ≤40min | 中（对比度） | 需一条实测证据 |
| 交互策略（滚动/跳转/筛选） | 2 文件 + 2 用例 | ≤1h | 中高 | 必须有复现用例 + 双内核验证 |
| 数据/构建（xlsx→JSON、ICS） | 4 文件 + 3 用例 + 重新生成产物 | ≥2h | 高 | 全量回归 + `git status` 干净 |
| 架构（拆文件 / 加依赖） | — | — | 极高 | **禁止**（见第 11 节） |

**时间盒**：第 1 轮 2h（全量分级）→ 第 2 轮 1h（只复核）→ 第 3 轮 0（只修阻断）。

python -m unittest discover -s tests -p "test_*.py"   # 47

npm run test:ui; npm run test:ui:webkit   # 冒烟 ×2

## 11. 不可回退红线（不能为了满足建议而破）

| 红线 | 守护方式 |
|---|---|
| 零依赖、单文件 `index.html` | 人工评审：新增 `<script src>`/依赖即拒 |
| 无网络请求、`file://` 可直开 | CSP `connect-src 'none'` |
| CSP 哈希制 + Trusted Types | `tools/verify.py`（每次构建校验） |
| 不用 `innerHTML` | 代码检索 + 评审（当前 0 处） |
| 手机优先：320px 不溢出、触控 ≥24px、图例各端可见 | `test:visual` 8 视口 |
| 构建确定性：build 后工作区干净、`.ics` CRLF、UID 稳定 | CI `git status` 检查 + `verify.py` |
| 五套测试全绿 + CI 绿才算"改完" | GitHub Actions |

## 12. 底线清单（这些没清完**不许停**）

对比度不达标 · 触控目标过小 · 320px 横向溢出 · 表单提交被阻断 ·
导出/导入不可逆 · `.ics` 无法订阅 · 首屏看不到下一节 · 数据会静默丢失 ·
CI 或测试红 · 合规/无障碍硬伤。

> 这些属于"不改会坏"，与"AI 还能挑出问题"无关，永远优先。

## 13. 暂不改清单（已知取舍 + 何时重开）

| 项 | 为什么不改 | 重开条件 |
|---|---|---|
| `设置.json` 的 `updatedAt` 仍是 2026-11-06 | 只影响 `validate_data.py` 提示 | 真发布前跑一次 `build.py --stamp` |
| 未捕获异常跳 `404.html` | 刻意设计：不带坏状态继续跑 | 出现"一次局部异常导致整页跳走且丢失操作"的真实反馈 |
| `SCROLL_EPSILON = 8px` 写死 | 实测阈值，配置化只增复杂度 | 真机复现"8px 判错" |
| 列表无虚拟化 | 165 行 render 5ms | 单班 >500 行 |
| 打印分页边界未逐页实测 | 只验了表头重复与元素隐藏 | 真需要打印交材料 |
| 卡片布局的 `conflict-join-*` 类无样式 | 桌面标记列仍依赖 | 桌面冲突标记改版时一并清理 |
| 「节次」允许任意文本（如 `abc` 也能存） | **用户明确不接受软提示**：自由文本是刻意保留的（`待定` 这类真实用法），无法解析时节次按全天事件导出 | 只有当「错节次导致差点错过实验」的真实反馈出现时再议 |
| 无 axe 自动化扫描 | 引入依赖违反红线 | 允许 devDependency 且不进产物时 |
| 真机读屏（NVDA/TalkBack）未验 | 环境成本高 | 有读屏用户反馈 |

## 15. 最终止损线

> **AI 只能提出"更好"，但提不出"不改会坏"的时候，就停。**
