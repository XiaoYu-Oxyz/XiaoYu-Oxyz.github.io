# CrseCue 止损点

> 这份文档是**内部决策依据**：约束"还要不要继续改"，不是功能说明。
> 一句话结论：**当 AI 只能提出"更好"、提不出"不改会坏"的时候，就停。**

---

## 1. 判断公式（每条改动过四问）

| # | 问题 | 答"否"的后果 |
|---|---|---|
| 1 | 它对应什么目标/指标？说不出来 | 不改 |
| 2 | 不改会不会造成实际损失？不会 | 不改 |
| 3 | 改了能否验证？不能验证且成本高 | 不改，或先验证再改 |
| 4 | 是否引入更大风险？会（破坏护栏、扩大回归面） | 不改 |

只做两类事：**有证据的硬伤**、**低成本高确定性的改进**。
主观审美、无法验证、收益递减的，一律止损。

**提案分级**（先贴标签再动手）：

| 级别 | 判据 | 处理 |
|---|---|---|
| 阻断 | 数据丢失、白屏、导出/订阅失效、手机无法操作、CI 红 | 立即修 |
| 高收益 | 有明确使用场景，改动小、可自测 | 修 |
| 锦上添花 | 措辞、颜色偏好、留白、图标风格 | **默认不做**，记入"暂不改清单" |

## 2. 双清单：什么算"目标已达成"

### 2.1 使用目标（有没有用）

| 目标 | 判据（自测，不靠审美） |
|---|---|
| 打开即知下一节课 | 首屏能看到「下一节 / 今天」提示条与最近一次实验，且该行完整可见 |
| 改完不丢 | 添加/编辑/删除/导入后刷新仍在；本机存储写失败时明确提示"本地保存失败" |
| 手机上单手能用 | 320–390px 无横向滚动，触控目标 ≥44px，编辑/删除按钮不出屏幕 |
| 数据能带走 | xlsx / JSON 可导出再导入；`.ics` 可被系统日历订阅，UID 稳定不重复 |
| 出错不乱跑 | 没有今天及以后的实验、目标被筛掉、课表视图 —— 均不产生意外滚动 |

### 2.2 质量门槛（有没有坏，当前实测值）

| 门槛 | 当前值 |
|---|---|
| 首行高度 | 320→363 / 360→317 / 390→296 / 768→283 / 1440→302 / 横屏 640×360→210 |
| 横向溢出 | 8 个视口全部 **0px** |
| 对比度 | 按钮文字 5.19–14.65；提示条 8.41；冲突描边 3.12（深）/3.5（浅）≥ 图形门槛 3:1 |
| 测试 | Python 42 · logic 52 · UI 冒烟 ×2（Chromium/WebKit）· 课表 50 · 视觉 8 视口 ×2 全绿 |
| 构建 | `validate → build → verify` 后 `git status` 干净；CSP 哈希与内联块一致 |
| 性能 | 200 条数据 → 165 行，`render()` 5ms、首屏 98ms |
| 导出/订阅 | 线上 `.ics` 为 `text/calendar`；UID = `hash(class\|date\|period\|name)` 确定性 |

**两条都满足**才算目标达成；只满足使用目标（但门槛破了）视为有 bug，不能停。

## 3. 六个止损信号（出现任意 2 条就停手）

1. **目标已达成、指标不再动**：上面两张表都达标，再改只剩"更清晰/更有冲击力"这类主观说法。
2. **意见开始重复、空泛、矛盾**：两轮建议互相冲突（比如先"加信息"又"减信息"），说明已进入审美分歧，不是问题发现。
3. **边际收益递减**：第一轮的硬伤（信息架构、移动端、表单、可读性、加载）都清了，后面只剩措辞、颜色、留白、图标。
4. **修改开始引入新风险**：破坏护栏（见第 5 节）、要改架构或加依赖、回归成本高于收益、开始"改 A 坏 B"。
5. **证据不足的大改**：要重做首屏、换叙事、改定位，却没有真实使用反馈支撑 —— 应先验证假设，不是继续微调。
6. **时间盒到线**：本轮 2 小时、第二轮 1 小时、第三轮只修硬伤；超时且无明确收益 → 冻结。

---

## 4. 流程

1. **第 1 轮**：允许全量提意见，但必须按「阻断 / 高收益 / 锦上添花」分级；只处理前两级。
2. **第 2 轮**：只允许复核已改项与硬伤，不再开放全量审美建议。
3. **冻结条件**（满足即冻结，不设固定日期）：双清单达标 + 硬伤清零 + 连续两轮无新增高优先级问题 + 时间盒用完。
4. **解冻条件**（随时可重开，但提案必须先有价值）：真实使用中碰到阻断/数据问题、部署环境变化（浏览器大版本、Pages 规则）、需求变化（新班级、新节次、新学制）。**"到期了"不是理由。**
5. 冻结后把放弃项写进第 6 节"暂不改清单"，等反馈再开。

## 5. 不可回退红线（不能为了改需求而破）

| 红线 | 现状 |
|---|---|
| 零依赖、单文件（`index.html` 内联 CSS/JS） | 保持 |
| 无网络请求、可离线、`file://` 直开可用 | `connect-src 'none'` |
| CSP 严格：哈希制、`require-trusted-types-for 'script'` | `tools/verify.py` 每次校验 |
| 不用 `innerHTML` | 当前 0 处 |
| 手机优先：44px 触控、320px 不横向滚动、图例各端可见 | 视觉冒烟守护 |
| 构建确定性：build 后 `git status` 干净、`.ics` CRLF、UID 稳定 | CI 守护 |
| 五套测试全绿 + CI 绿才算完成 | 当前 run 28 SUCCESS |

## 6. 暂不改清单（已知但不做，等反馈再开）

| 项 | 为什么不改 |
|---|---|
| `data/设置.json` 的 `updatedAt` 仍是 2026-11-06 | 只影响 `validate_data.py` 的提示；`build.py --stamp` 随时可刷，不急 |
| 任何未捕获异常会跳 `404.html` | 是刻意设计（不带坏状态继续跑）；代价是局部异常整页跳走，接受 |
| `SCROLL_EPSILON = 8px` 写死 | 8px 是实测出的"几乎完整可见"阈值，放进配置只会增加复杂度 |
| 列表无虚拟化 | 165 行 `render()` 5ms，上千条才值得做 |
| 打印分页边界未逐页实测 | 只验证了表头重复与元素隐藏；真需要打印时再看 |
| `conflict-join-top/next` 在卡片布局无样式 | 桌面标记列仍依赖，属无害冗余，删除反而有回归风险 |
| 冷启动定位不播报**滚动距离** | 只播报"已定位到 …"，多说无益 |
