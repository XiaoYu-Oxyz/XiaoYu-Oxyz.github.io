# 新学期怎么开始

> 学期结束那天，这个页面的价值会归零：所有实验都变成"已结束"，默认筛选项会把它们全藏起来。
> 这份文档只回答一件事：**下一个学期，从零到能发到群里，按什么顺序做。**
>
> PRD 明确不做"多学期"（数据结构要加一维，收益不抵复杂度）。所以新学期的做法是**覆盖**，
> 不是并存：旧数据留在 git 历史里，页面上只显示当前这一学期。

## 0. 先定两件事

| 要定什么 | 为什么 |
|---|---|
| 班级还是那几个 | 班级 = `data/<班级名>.xlsx` 的文件名，改名等于换班 |
| 第 1 周的星期一是哪天 | `week1`，**必须是星期一**，build 会校验 |

## 1. 换数据

- 覆盖 `data/Z1.xlsx` / `Z2.xlsx` / `Z5.xlsx`（文件名就是班级名）。
- 表头必须有：`节次`、`实验名称`、`实验地点`，加 `日期` **或** `周次`+`星期` 之一。
- 最省事的做法：在旧页面上「操作 → 导出」拿到一个格式正确的 xlsx，把里面的行替换掉。
- 节次统一写成 `第3-4节` 这种带"第"和"节"的写法，解析最稳。

## 2. 改第一周

- 全局：改 `data/设置.json` 的 `week1`（如 `"2027-02-22"`）。
- 某个班的第一周不一样：在该班 xlsx 的 `班级信息` 页写一行 `week1`，它优先于全局值。
- 顺手确认 `periodTimes`：作息变了（比如晚课改成 19:30）就在这里改 `1-2` / `3-4` / `5-6` 这些键。

## 3. 体检 → 构建 → 校验

```powershell
cd D:\MyProgram\HTML\CrseCue\XiaoYu-Oxyz.github.io

python tools\validate_data.py       # 先把问题一次列全，不改文件
python tools\build.py --stamp       # 写页面 + 日历，并把 updatedAt 写成本机今天
python tools\verify.py              # CSP 哈希 / 模板 / 编码
```

记住两条：

- `--stamp` 会改 `data/设置.json` 的 `updatedAt`。**只在真的换了数据时跑**，否则页面会谎报"今天更新"。
- 这个顺序是"改数据"的顺序。如果同时改了 `index.html` 的 `<style>`/`<script>`，要**先** `python tools\verify.py --apply` 再 build，否则整页白屏。

## 4. 发布

```powershell
git add -A
git commit -m "data: 新学期课表"
git push
```

或者不装 Python：GitHub 网页 → **Actions → update-data → Run workflow**（勾 `stamp`）。
前提是 Settings → Actions → General → Workflow permissions 选了 "Read and write permissions"。

推送后等 1–3 分钟生效。看不到变化就先 `Ctrl+F5`。

## 做完自查

- [ ] 页面顶部显示「数据更新至 <今天> · 今天」
- [ ] 默认勾选的「已结束仅显示本周」下，首屏是本周的实验
- [ ] 班级下拉还是那三个班，条数对得上
- [ ] 手机上看一眼：首行没被顶出屏幕，没有横向滚动
- [ ] 日历订阅地址没变（`https://<站点>/calendars/<班级>.ics`），学生那边下次同步会自动更新

## 学生会碰到的三件事

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 「本机改动基于旧版本」提示 | 他在旧学期改过数据，本机存着一份覆盖 | 让他导出备份，或点「恢复」重新载入 |
| 还是旧课表 | 浏览器缓存了 HTML | `Ctrl+F5`，或无痕窗口 |
| 群里的旧链接打不开 | 不会发生：`?class=Z1` 与学期无关 | —— |

## 旧学期去哪了

- 页面不再显示（被覆盖），但 git 历史里在。
- 想留档：发布前打个 tag，`git tag 2026-秋 && git push --tags`。
- 别想着"两个学期一起放"：`week1` 只有一个，混着放会让周次和日期对不上。
