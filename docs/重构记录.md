## 2. 六个阶段做了什么

### 段 1 · 构建链（`4a3ba2f`）

| 改动 | 证据 | 效果 |
|---|---|---|
| 校验函数抽成纯函数 `verify_html/verify_bytes/apply_hashes_to_html` | `tools/verify.py` | 构建可在**写盘前**校验 |
| 构建先校验内存产物、再原子写盘 | `tools/build.py:main()` | 哈希过期/模板损坏/危险 sink → 非 0 退出，**两个 HTML 一字节不动**（已实测：改一个空格后 build 失败、`index.html` 的 SHA256 与 mtime 均未变） |
| `updatedAt` 从 git 提交日改为 `data/设置.json` 显式字段 + `--stamp` | `data/设置.json`、`tools/build.py` | 本地构建与 CI 构建不再必然产生 diff，`git diff --exit-code` 不再误报 |
| 新增 `\r`/裸 CR/NUL 检查 | `tools/verify.py` | 抓"校验通过但浏览器拒执行"的一类静默白屏 |
| `--apply` 用 `re.subn` 断言替换数量 | `tools/verify.py` | 哈希没替换成功会报错，而不是打印 "updated" |
| 两个 `.bat` 全部加 `errorlevel` 中止 + `%~dp0` + openpyxl 检查；上传脚本先构建再推 | `部署文件.bat`、`上传文件.bat` | 断掉"白屏产物被推上线"的链条 |
| CI 拆成 build / ui 两个 job，matrix 双引擎，加 `timeout-minutes`、`concurrency`，产物不一致时打印可操作提示 | `.github/workflows/verify.yml` | 失败信息可执行，不再只有一行 diff |
| **`index.html` 定为唯一真源**，`实验提醒.html` 降为同步副本 | `tools/verify.py`、`tools/build.py` | 消除"改错文件被覆盖"的陷阱（重构过程中真实踩过一次） |

### 段 2 · 样式与首屏（`66a7117`）

- **页头三块化**：`head-row/head-title` → `header.head` = `head-main`（标题+班级）/`head-filters`（两个复选框+计数）/`head-actions`（复制本周、操作）。手机端用 grid + `display:contents` 排成「标题+操作 / 班级 / 筛选」三行。
- **首屏压缩**：`.wrap` 手机端改纵向 flex，用 `order` 把「第 1 周星期一」挪到表格之后；隐藏手机端图例（卡片自带文字标签）与「数据更新至」；时钟压到 12px。347 → 166px，**不动 DOM 结构**。
- **卡片首行裁切修复**：删除 `771` 的 `nowrap + overflow:hidden`，`832` 补 `overflow-wrap:anywhere` 与 `flex:none` 标签。
- **对比度**：`row-past` 文字、三种 tag 底色、卡片边框。
- **焦点可见**：全局 `:focus-visible` 纳入 `input`/`[tabindex]`；6 处 `:focus{outline:none}` 改为 `:focus:not(:focus-visible){outline:none}`，光晕透明度 .15 → .35。
- **悬停**：`filter:brightness()` → `@media (hover:hover)` 背景色，消除 `border-collapse` 下的 1px 暗缝与"今天"被压暗。
- **深色模式**：`:root{color-scheme:light dark}` + 30 行显式覆盖（面/字/边/五种状态色）。
- **平板**：561–940px 两列卡片网格；≤400px 隐藏「班级：」文字标签，班级名不再被压成 73px。
- **打印**：`body/.wrap` 的 `padding:0` 补 `!important`（原来被 940px 块反向覆盖），`break-inside:auto` 允许长备注跨页，备注字号 9.5px → 8.5pt；**`.head-row` 改名后打印规则同步改为 `.head`**（否则页头会印出来）。
- **弹窗**：`max-height: min(92dvh, 640px)`（跟随手机键盘）+ `safe-area` 底部内距。
- 另加：触屏 `:active` 反馈、`prefers-reduced-motion`、复选框 18px、复制/操作按钮 36px 高。

### 段 3 · 结构（`ba5c027`）

- **roving tabindex**：`render()` 生成行时 `tabIndex = -1`，由 `syncRowFocusability()` 只把当前行设 0；`focusin` 同步当前行。25 行 → 1 个 Tab 停靠点，方向键仍是逐条移动，Esc 回表格。

### 段 4 · 功能（`ba5c027`）

- **日历导出 `.ics`**：`操作 → 数据 → 日历（.ics）`，生成标准 `VCALENDAR`：
  - 每班一个文件 `${班级}-实验课.ics`；每条实验一个 `VEVENT`
  - 节次映射 `1-2→08:00-09:40 / 3-4→10:00-11:40 / 5-6→14:00-15:40 / 7-8→16:00-17:40 / 9-10→19:00-20:40`，无法识别时退化为全天事件
  - `VALARM TRIGGER:-PT2H`（提前 2 小时），`VTIMEZONE Asia/Shanghai`，按 RFC 5545 转义并在 75 字节处折行
  - 实测：25 条事件 / 25 个提醒 / 只有 CRLF / 最长行 48 字节 / 页面零报错
- 这是纯静态页面唯一能做到"真正提醒"的路径：导入系统日历后由 OS 负责弹通知，不需要任何后端，也不违反 `connect-src 'none'`。

### 段 5 · 测试

- 新增 `.ics` 端到端断言（下载文件名、`BEGIN:VCALENDAR`、`VTIMEZONE`、事件数等于 `#recentCount` 的总数、75 字节折行）。
- 修掉实测 1/3 概率变红的那条竞态断言（`ui-smoke.mjs:416`）：不再断言状态栏文案，改为等「撤销」按钮出现（状态栏会被并发的跨标签页同步消息覆盖）。
- 更新 roving tabindex 的键盘断言（1 个行级停靠点 + Tab 离开表格）。

### 段 6 · 文档

- README：工作表选择规则（优先 `实验安排`）、`updatedAt`/`--stamp`、构建先校验后写盘、`index.html` 为唯一真源、手机端布局与首屏数字、roving tabindex、深色模式现状、`.ics` 用法、部署路径修正（`D:\MyProgram\HTML\实验提醒` → 真实路径）。

## 3. 刻意没做的（含理由）

| 项 | 理由 |
|---|---|
| 抽 CSS 变量（304 处硬编码） | 逐条替换 `#fff` 这类值必须区分为"面"还是"字"，机械替换在深色下会出错；收益只是可维护性，风险是整页配色崩。深色模式已用显式覆盖实现，真正的 token 化应作为独立提交。 |
| 去掉桌面 46px 空列 | 该列同时是**冲突标识轨道**（`tbody tr.row-conflict td.cell-mark`），去掉会破坏冲突可视化。 |
| `data.json` 懒加载 | gzip 后只省约 10KB，却要放开 `connect-src` 并放弃"单文件可拷走"。 |
| 虚拟滚动/分页 | 2000 条时 `render()` 36ms，当前 65 条离阈值很远。 |
| 冲突色改斜纹 | 现有"同组相邻行连成一条"的边框配色体系与该单元格背景强耦合，斜纹会破坏合并效果，收益小于风险。 |

## 7. 第 3 轮补充（404 页纳入加固 + 校验器单测）

### 7.1 404.html 收进同一套 CSP

原来 404 是唯一没有 CSP 的页面，且带三处与严格 CSP 冲突的写法：

| 问题 | 原写法 | 改法 |
|---|---|---|
| 内联事件属性 | `<button onclick="history.back()">` | 换成 `id="backBtn"` + 现有脚本里 `addEventListener` |
| 内联样式属性 | 5 处 `style="--d:.05s"` 交错动画延迟 | 改成 `.d1`–`.d5` 类，`--d` 写在样式表里 |
| 占位邮箱 | `mailto:hello@example.com` | 改为指向仓库 issues 的链接 |

随后加上与其他页面同一套哈希 CSP，`tools/verify.py --apply` 会一并更新 404 的哈希，校验时会检查：哈希匹配、`default-src 'none'`、`connect-src 'none'`、`base-uri/form-action 'none'`、无外部 `<script src>/<link>/<img>`、无内联事件属性、无危险 DOM sink。

实测（Chromium + WebKit）：**0 条 CSP 违规**、样式表 43 条规则生效、canvas 正常绘制、`--d` 延迟正确、返回按钮可用、控制台无错误。

### 7.2 校验器单测 `tests/test_verifier.py`（16 例）

覆盖"构建先校验后写盘"所依赖的每一项判断：哈希过期、缺模板、危险 sink、CRLF、裸 CR、NUL、BOM、外部脚本、内联事件、`--apply` 修复与幂等性。

顺带修了两个诊断质量问题：`<script src>` 现在报"外部脚本"而不是"内联脚本数量不对"；`<meta ... />` 自闭合写法现在能正确匹配（之前 404 的 meta 匹配不到，导致 `--apply` 直接崩）。

## 8. 第 4 轮补充（首次访问提示 + 诊断信息）

**F4 首次访问提示**：没有 `?class=` 且本机没存过班级时，表格上方出现一次提示「当前是 Z1，不是你的班？在上方「班级」切换。」，切换班级或点 × 后消失并记住选择。

### 8.1 抓到一个我自己引入的回归

`.wrap` 在手机端是纵向 flex，新加的「首次提示」和「诊断信息」忘了写 `order` → 默认 0，被排到了 `order:2..6` 的表格**前面**。复测立刻暴露：390px 首行从 166 涨到 **252**，诊断链接还出现在表格上方。

### 8.2 字号阶梯（U9）做了可验证的那一半

原报告说"13 档字号"。实测定位后，真正的问题不是档位多，而是**有一个 UA 默认值在泄漏**：

```css

button#newClassBtn, input#recentFilter … → 13.3333px
```

给表单控件加 `font-size: inherit` 后，13.3333px 消失（12 档，且都是设计里显式写过的值），布局零变化（320→192、390→166、1440→248，无横向溢出）。

**没有做的**：把 12 档硬压成 6 档。那属于视觉设计走查（每档都对应真实层级），机械合并会改观感；而报告里"最重要的状态语义反而最小"这条实质问题已在第 2 轮修掉（`.tag` 11→12px、`.next-badge` 10.5→11.5px）。

## 14. 第 10 轮（节次时间端到端 + 数据体检 + 无障碍补完）

这一轮不是"加功能"，而是把三件一直模糊的事定死：**课几点上**、**数据对不对**、**高对比度下看不看得出状态**。

### 14.1 节次时间：从硬编码到三层配置

之前 5-6 节写死 `14:00–15:40`，而且只影响 `.ics`；页面提示条完全不知道自己几点上课。

| 层 | 位置 | 说明 |
|---|---|---|
| 默认 | `tools/build.py` 的 `DEFAULT_PERIOD_TIMES` | 5-6 节按实际调整前移到 **13:30–15:10** |
| 全站 | `data/设置.json` 的 `periodTimes` | 只写要覆盖的键，其余回落默认 |
| 班级 | 班级 xlsx `班级信息` 页同名行（JSON 字符串） | **优先级最高**，留空则跟随设置 |

构建时合并成每班一份，注入 `<template id="defaultData">`；页面再叠加一层本机覆盖（导入的班级备份带 `periodTimes` 时写入 `localStorage` 的 `classtimes:v1:<班>`）。

消费方三处：日历事件时间、提示条文案（「第5-6节（13:30–15:10）」）、页面导出的 `.ics`。提醒提前量统一为 **30 分钟**（`REMINDER_MINUTES`），`build` 与页面两边都从同一常量取值。

验证：`Z1.ics` 出现 `T133000` / `T151000` / `TRIGGER:-PT30M`；页面 `resolvePeriodTimes('第5-6节')` 返回 `13:30–15:10`；`logic.mjs` 比对页面导出与文件仍一致。

### 14.2 导入时提示"文件内部重复"

判重口径**直接复用合并去重**的 `expIdentity()`（日期 + 节次 + 名称，NFKC/去空白/统一横线后比较），所以不会出现"提示了重复但导入没去掉"的错位。注意点：`第 3-4 节` 与 `第3-4节` 会被判为同一条。

实测导入一个含 2 条相同记录的 JSON：弹窗出现「文件里有 1 条疑似重复（同日期、同节次、同名称），合并模式下只保留第一条」。

### 14.3 数据体检脚本 `tools/validate_data.py`

`tools/build.py` 遇到第一个错误就 `SystemExit`，不适合"改完 Excel 先看一眼"。新脚本把所有能查的问题一次列全，且**不修改任何文件**：

```
检查 3 个班级文件，共 65 条实验
  [x] Z3.xlsx：班级信息写的是「别的名字」，与文件名不一致
  [x] Z3.xlsx 第 3 行：节次「第99节」超出 1-14 的范围
  [x] Z3.xlsx 第 3 行：日期「2026/11/09」必须是 YYYY-MM-DD
  [!] Z3.xlsx：第 5 行与第 4 行疑似重复（2026-11-16 第5-6节 重复实验）
```

输出只用 ASCII 标记（`[x]` / `[!]`）：Windows 控制台是 GBK，第一次用 `⚠`/`✗` 直接抛 `UnicodeEncodeError` 崩了。已接入 CI（build job 的第一步）。

## 24. 第 19 轮（发布上线 + CI 三处修复）

52 个提交推上去后，CI 连续红了三次，每次都是**本地全绿、Linux 红**。

### 24.1 产物一致性检查：.ics 行尾

`Ensure generated files are committed` 失败。干净克隆复现后确认：

```
仓库里的 Z1.ics：8630 字节，LF
构建写出的 Z1.ics：8997 字节，CRLF
```

`.gitattributes` 只写了 `* text=auto`，于是 git 把 `.ics` 当文本，提交时**把 CRLF 归一化成 LF**。而 `tools/verify.py` 明确要求 `.ics` 必须是 CRLF（iCalendar 规范）。Windows 上因 `autocrlf=true` 工作区仍是 CRLF，所以本地永远看不出来；Linux 检出是 LF，构建写 CRLF → 判定"产物与提交不一致"。

修法：`.gitattributes` 加 `*.ics -text`，让 git 原样存取。副产物是 **Pages 上真正对外提供的 .ics 也终于变成 CRLF**（此前是 LF，违反自家校验器的要求）。

### 24.2 CJK 字体：几何断言全平台漂移

## 28. 第 23 轮（冲突圆角描边 + 最短对角连线 + 分隔线严格居中）

### 28.1 冲突：从"左侧竖条"改成"整卡描边"

### 28.2 关联：最短对角线段

1. 按 `computeConflictInfo().byIndex` 把"当前可见"的冲突行按组聚合；

```css
}
```

## 34. 第 29 轮（打开时的定位改成"可见就不动，看不全才最小滚动"）

### 34.1 之前为什么"有时跳、有时不跳"

旧实现有 4 个提前返回，其中最要命的是这条：

```js
if (target.getBoundingClientRect().top <= window.innerHeight * 0.6) return;  // 目标已在首屏上半部分就不跳
```

它判断的是"目标在不在视口上 60%"，而不是"目标是否完整可见"。列表短、筛选后行少、浏览器恢复了滚动位置，都会命中这一条 → 看起来时灵时不灵；另外课表视图、全部已结束、`autoLocated` 只跑一次，也都是"不跳"的来源。

### 34.2 新规则（按用户确认的 6 条）

1. **只在冷启动判断一次**（刷新算一次；切班级/改筛选/跨天刷新都不再滚动）；
2. **顶层安全区扣掉吸顶表头**；
3. **那一天的所有条都要完整可见**才算"看见了"；
4. 看不全时按**最小距离**滚动：
   - 下面看不全 → 只滚 `groupBottom - viewportBottom`；
   - 上面被表头挡住 → 只滚 `groupTop - safeTop`；
   - 整组比安全区还高（退化情形）→ 组首贴住安全区顶部；
5. 没有今天及以后的实验 → 不动；课表视图 → 不动；
6. 可见时不加任何动画，只保留行上的蓝色描边 +「今天 / N天后」标签。

### 34.3 两个实现坑（都踩过）

- **吸顶表头量错**：卡片布局下 `thead` 被 `position: absolute` + `clip` 隐藏，但里面的 `th` 仍是 `position: sticky`，直接取 `th.getBoundingClientRect().bottom` 得到 **296px**（整页高度级），把安全区吃掉一半，滚动距离算出 52px 而不是 349px。现在先判 `thead` 是否 `absolute`，并且只用 `th` 的**高度**（42px）而不是当前 `bottom`——表格停在页面顶部时表头还没吸顶，`bottom` 会把上面整块头部算进去（实测 301px）。
- **不要挪到 load / rAF 之后再执行**：试过 `load + 双 rAF`，结果 WebKit 视觉冒烟里"关掉提示条应回落 42px"变成 49px（被迟到的滚动顶了 7px）。同步执行（脚本在 `</body>` 前、早于首次绘制）既不会"先看到顶部再跳"，也不会和"打开时滚到顶"的逻辑抢滚动位置。

## 35. 第 30 轮（提示条跳转也改成最小移动）

### 35.1 修改前

```js
row.scrollIntoView({ block: 'center', behavior: 'smooth' });   // 固定滚到屏幕正中
```

两个毛病：**已经看得见也照样动**（每次都把行拉到正中心），和冷启动刚定下的"可见就不动"完全相反。

### 35.2 修改后

冷启动和提示条跳转抽成同一套工具函数：

| 函数 | 作用 |
|---|---|
| `rangeScrollDelta(top, bottom, safeTop, safeBottom)` | 纯计算：已完整可见返回 0；整组超一屏 → 首端贴顶；下方看不全 → `bottom - safeBottom`；上方被挡 → `top - safeTop` |
| `scrollRangeIntoView(top, bottom, smooth)` | 按上面算出的距离 `scrollBy`，尊重 `prefers-reduced-motion` |
| `ensureElementVisible(el, smooth)` | 单元素版，提示条跳转（列表行 / 课表格子）都用它 |

实测（360×640，目标在折叠下方）：点击后 `scrollY` 从 0 → **127**，目标底边正好贴到 640（居中需要滚 380+）。目标已完整可见时点击：`scrollY` 280 → **280**，一动不动，只有 1.6s 闪烁。

### 35.3 测试

`ui-smoke` 新增第 16 段：

- 目标在折叠下方 → 点提示条后 `bottom === 视口高`（±1px），且滚动量小于"居中所需"；
- 目标已完整可见 → 点提示条后 `scrollY` 不变。

写测试时踩了个坑：Playwright 的 `.click()` 会**先把提示条滚进视口**再点，导致测出来"点完回到顶部"。改用 `document.getElementById('cueText').click()` 走 DOM 点击，并 `reducedMotion: 'reduce'` 让滚动立即生效，断言才稳定。

### 35.4 关于"启动都不跳了"

复查了一遍：目标**看不全**时启动确实会滚（360×640 实测 527px，目标底边贴到视口底）；目标**已完整可见**时按约定不滚（实测 `scrollY=0`）。所以"不跳"是规则生效，不是坏了。

### 40.2 坑一：`::after` 扩热区挡住了 `<input>`

第一版照搬 `.cue-close::after` 的手法（伪元素盖一层、不占布局）。结果 **`test:ui` 在 Chromium 和 WebKit 双双超时**：

```
page.uncheck: Timeout 30000ms exceeded.
  - <label class="recent-filter">…</label> intercepts pointer events
```

原因是覆盖层压在 `<input>` 上，Playwright 的可点击性检查过不去，读屏落焦也会落到 label 而不是复选框。
改成 `padding` + 负 margin 后，`<input>` 仍在自己中心被精确点到，热区照样是 30px。

**教训**：`::after` 扩热区只适用于"元素本身就是点击目标"（按钮、关闭叉）；**包着 `<input>` 的 label 不能用**。

## 41. 第 36 轮（操作面板按钮被压到裁字 + 换行修复）

### 41.1 现象

`nowrap` 禁止换行，`flex: 1 1 auto` + `min-width: 0` 又允许按钮缩到内容宽度以下 → 一行塞满、逐个裁字。

### 41.3 修复

```css
.action-groups { flex-wrap: wrap; gap: 6px; row-gap: 6px; }
.action-group  { flex: 1 1 auto; flex-wrap: wrap; gap: 4px; min-width: 0; }
.action-group > button { flex: 0 0 auto; }   /* 按钮永远保持自身宽度 */
```

| 330 / 360 / 390 / 430 / 500 | 2 | 0 | 0 | 44px |
| 664 / 800 / 940 | 1 | 0 | 0 | 44px |
| 941+（桌面） | 3（原有布局） | 0 | 0 | 36px |

```js
const isNext = !!nextDate && e._date.getTime() === nextDate.getTime();   // 今天/明天也会命中
```

```js
const nextIsImminent = nextDays === 0 || nextDays === 1;   // 就今天/明天
const nextHighlightable = !!nextDate && !nextIsImminent;
const isNext = nextHighlightable && e._date.getTime() === nextDate.getTime();
```

## 51. 第 46 轮（变量化之后的第一轮复查：抓到一个深色打印 bug）

### 51.1 复查方法

变量化是"值等价替换"，理论上不会带来功能变化。所以这轮不再看截图，而是做四类针对性探测：

1. 打印渲染（浅色/深色两套 scheme 真截图）；
2. Windows 高对比度（`forced-colors: active`）渲染；
3. CSS 规则是否被浏览器丢弃（统计空声明规则）；
4. `<style>` 之外是否还有颜色字面量（内联 style / JS 拼色）。

### 51.2 抓到的 bug：深色模式下打印是黑底浅字

第 1 项就露馅了：深色模式下 `emulateMedia('print')` 截图整页是**黑底**，标题是浅色字。

原因：打印样式块（`@media print`）在深色块**之前**，两者对 `body` 都是 `(0,0,1)` 特异性，
深色规则更靠后所以赢：

```css
/* 打印块（在前） */
body { background: var(--c-fff); color: var(--c-000); }   /* 没有 !important */
/* 深色块（在后） */
body { background: var(--c-0d1117); color: var(--c-e6edf3); }   /* 赢了 */
```

后果：浏览器关闭"背景图形"（默认）时，黑底不打印，但**浅色文字照打** → 标题几乎看不见；开着背景图形则整页耗墨。

修复（4 处 `!important`，以及 `.wrap` 底色）：

```css
body { background: var(--c-fff) !important; color: var(--c-000) !important; }
.wrap { background: var(--c-fff) !important; }
.print-head { color: var(--c-000) !important; }
th { color: var(--c-000) !important; }
```

修完浅色/深色两套 scheme 的打印计算值都是 `body=rgb(255,255,255) / color=rgb(0,0,0)`，
表头黑字浅灰底，标题黑字。

- **高对比度模式**：所有行正常渲染（今天/明天的区别退化为标签文字 `今天 •` / `明天 ▲` + 更粗描边，信息不丢）；

- **`<style>` 之外**：颜色字面量 0 处、内联 style 0 个、JS 里 `rgb(` 0 处。

### 51.4 加固

## 54. 第 49 轮（G1：源码拆到 src/，产物仍是单文件）

### 54.1 为什么这么拆

直接拆成 `index.html + app.css + app.js` 会让 CSP 从 `'sha256-…'` 退回 `'self'`，
而 `file://` 下的 `'self'` 行为不一致 —— 双击本地文件可能白屏，等于砸掉"发一个文件给同学"的用法。

所以拆的是**源码**，产物仍是单个 `index.html`：

```
src/index.template.html   ← 页面骨架，含 /*__CRSECUE_CSS__*/ 与 /*__CRSECUE_JS__*/ 占位
src/app.css               ← 80KB，原 <style> 内容
src/app.js                ← 209KB，原 <script> 内容
index.html                ← build 把三者内联 + 按实际内容重算 CSP 哈希
```

### 54.2 改动

- `tools/build.py`：改为读 `src/` 模板与两个源文件，内联后调用 `verify.apply_hashes_to_html()` 重算哈希，再校验、写盘；
- 新增 `python tools/build.py --check`：只比对 `index.html` 是否与 `src/` 同步，不写盘（本地防漂移）；
- 产物与拆分前**字节一致**：`sha256 = 0A8C927A…`，`git diff index.html` 为空。

### 54.3 一致性怎么保证

- CI 的构建 job 跑 `build.py` 后 `git status --porcelain` 必须干净 → `src/` 与产物不同步会被拦；
- 本地随手 `--check` 也能发现；
- 哈希不再是"手改后忘记 --apply"的雷：build 每次按内联内容重算。

```
Python 49/49 · UI 冒烟 ×2 · 课表 50 · 视觉 ×2 · color_audit —— 全绿
产物字节与拆分前一致：INDEX sha256 0A8C927A…
```

## 57. 第 52 轮（修复两列布局「横不对齐」）

### 57.1 现象

两列卡片里，同一行的普通卡与冲突卡文字差 1px：冲突卡是 `border: 2px`，普通卡是 `1px`，
盒模型多出来的 1px 把整张卡的内容往下推。用户的截图正好是这一对。

### 57.2 修法

把冲突的"视觉 2px"改成 **1px 边框 + 1px 内阴影**：

```css
@media (max-width: 940px) {
  tbody tr.row-conflict,
  tbody tr.row-next.row-conflict {
    border-color: var(--row-conflict-border);
    box-shadow: inset 0 0 0 1px var(--row-conflict-border);
  }
  /* peer / 已结束各用各自语义色，同样补内阴影 */
}
```

要点：

- 边框仍是 1px → 盒模型与普通卡一致，文字对齐（实测同一行 `contentTop` 都是 284.0）；
- 视觉厚度仍是 2px（1px 边框 + 1px 内阴影），方角、颜色不变；
- 规则放在样式表末尾的 `@media (max-width: 940px)` 里，压过各断点与深色块的 `box-shadow`；
- `row-next` 的蓝内阴影在冲突行上让位给琥珀色（冲突优先，和之前一致）。

### 57.3 守护

- `ui-smoke` §13 从"断言 2px 边框"改成"1px 边框 + `inset` 内阴影"；
- 新增 §28：700px 两列下构造"普通卡 + 冲突卡"，断言两者 `top` 相同且 `contentTop` 完全相等。
